# ioc v0.2.0

This release adds HTTP route compilation and a separately versioned Gin adapter.

## HTTP annotations

- Register managed Controllers with `+ioc:controller`, including component names,
  aliases, field injection, conditions, profiles and lifecycle hooks.
- Declare a Controller base path with `+ioc:http:route` and handler mappings with
  the structured `method`/`path` form or HTTP method shortcuts.
- Generate typed bridges for private Controller methods and standalone handlers
  in their declaring packages. Unannotated methods are not exposed as HTTP endpoints; no reflective route discovery or invocation is introduced.
- Expose the `pkg/codegen/http` backend boundary through `codegen.Options.HTTP`.
  Source notices, formatting, overlay type checking and output persistence remain
  part of the common generation pipeline.

## Gin adapter

The adapter is published as `github.com/longxi-go/ioc/adaptors/gin@v0.2.0`, using
repository tag `adaptors/gin/v0.2.0`. Install its generator with:

```sh
go install github.com/longxi-go/ioc/adaptors/gin/cmd/ginctl@v0.2.0
```

- Generate native Gin route descriptors and aggregate them at the application
  entry with `IOCGinRoutes`.
- Register routes after application startup. Excluded conditional Controllers
  contribute no routes; active route conflicts fail assembly.
- Resolve singleton or request Controllers with the incoming request context.
  Request-scope middleware closes managed resources after normal completion,
  abort, cancellation and panic.
- Keep Gin runtime packages independent of generator packages and the root module
  independent of Gin dependencies.

## Examples and documentation

The Gin integration and Coffee MVC application use generated routing. Coffee
retains SQLite persistence, HTML and REST endpoints, generated configuration
binding, conditional components, events and managed cleanup. The bilingual manual
includes the HTTP annotation reference, adapter boundaries and integration flow.

## Compatibility

Ordinary IoC annotation and lifecycle semantics remain unchanged. HTTP generation
requires the adapter-enabled `ginctl`; the root `ioctl` rejects HTTP endpoints
without a selected backend. Native handlers use `func(*gin.Context)`.
Controller route generation supports singleton and request lifetimes. HTTP route
publication through `--library`, dependency-module HTTP discovery, request-binding
annotations and middleware annotations are not included in this release.

Pin the adapter and root module versions together and regenerate HTTP application
output when upgrading.
